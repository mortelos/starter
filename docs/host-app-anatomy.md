# Host App Anatomy

What a working MortelOS host app looks like on disk. This template starts at
the **out-of-the-box** column; portal work grows it toward the **fleshed-out**
column. Use complete internal MortelOS host apps for shape and intent when this
template doesn't yet ship the bit you need.

## What lives where (cheat sheet)

| Concern | Lives in | Why |
| --- | --- | --- |
| Layout shell | `resources/views/layouts/app.blade.php` (+ `guest.blade.php`) | Ships with the template |
| Auth pages (login Livewire SFC) | `resources/views/livewire/pages/auth/login.blade.php` | Ships |
| Auth controllers (logic) | `app/Http/Controllers/Auth/` | Working defaults; replace with real auth flow per portal |
| Post-login redirect | `app/Actions/Auth/ResolvePostLoginRedirect.php` | Ships returning `/dashboard`; make role-aware per portal |
| User model | `app/Models/User.php` | Laravel default; extend with tenant/membership traits per portal |
| Tenant resolution | host-owned (e.g. `app/Support/StanclTenantResolver.php`) | Each host picks its tenancy strategy |
| Navigation tree (sidebar) | `app/Support/StarterSidebarNavigationResolver.php` (host-owned) | Bind via `config/starter.php` `navigation.sidebar_resolver` |
| Universal search results | `app/Support/StarterUniversalSearchResolver.php` (host-owned) | Bind via `navigation.universal_search_resolver` |
| Governance access (canManage) | `app/Support/StarterGovernanceAccessResolver.php` (host-owned) | Bind via `governance.access_resolver` |
| User management actions | `app/Support/StarterUsersResolver.php` (host-owned) | Bind via `users.resolver` |
| Dashboard widgets | `app/Livewire/Dashboard/` or a package | Choose per `package-now` / `-ready` |
| Policy abilities | `app/Policies/` | Host seeds defaults; Policy Studio reviews changes |
| Connectors (Moneybird, Fireflies, etc.) | `packages/<connector>/` (path repo) or composer dep | Reusable across MortelOS installs |
| Portal capability docs | `docs/portals/<slug>/` | Per-portal; tracked in git |
| MCP server mount | `routes/ai.php` | Host mounts; server is provided by `mortelos/framework` |

## Test accounts (host seeded)

The template seeds one account:

| Role | Email | Password |
| --- | --- | --- |
| Admin | `admin@example.test` | `password` |

Add account-manager, customer, and inspector accounts in the host's
`DatabaseSeeder` as the portal's role model is specified:

```php
User::factory()->create([
    'name' => 'Account manager',
    'email' => 'am@example.test',
    'password' => Hash::make('password'),
]);
```

The verification checklist in [`knowledge/07-test-and-verify.md`](../knowledge/07-test-and-verify.md)
refers to these accounts.

## What the agent should produce after the first portal slice

A correctly-built first vertical slice has, in addition to what the template
ships:

- [ ] The capability written up in `docs/portals/<slug>/capability-map.md`
- [ ] A package decision recorded in `.mortelos/package-decisions.md`
- [ ] The domain modelled as entities/links/events under `mortelos/framework`'s
      primitives
- [ ] At least one projection with rebuild + verify behavior
- [ ] A surface (starter page, package route, dashboard widget, chat widget,
      page widget) wired
- [ ] A deny-by-default policy ability for any mutating action
- [ ] A Pest feature test under `tests/Feature/<Capability>/`
- [ ] `php artisan starter:doctor` still green
- [ ] `vendor/bin/pest` still green
- [ ] Manual verification checklist handed to the user
